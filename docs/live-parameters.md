# Private block parameters and device notifications

Release 0.22.0 connects the contained model-specific editor catalogues to live block tables and private parameter echoes. FM9, FM3 and both Axe-Fx III capacity definitions use the same implementation with their own addresses. Supported saved editing, live controls and public notification decoding remain enabled. This release adds software validation, not hardware qualification.

## Read a current block

`read-block-parameters --model MODEL --capacity CAPACITY --firmware VERSION --input INPUT --output OUTPUT --effect-id INSTANCE --destination NEW_DIRECTORY` queries one explicitly selected, currently present instance. `--network IPV4:CONTROL_PORT` replaces native ports. `--timeout SECONDS` bounds each exchange; `--validate-only true` validates arguments without opening a connection.

MCP `fractal_read_block_parameters` takes `effect_id` (1–1000), uses the configured device/transport and existing live-read access, and returns a private evidence artifact. It does not authorize edits or navigation. The report is `parameters/parameters.json`; complete received transfer frames are retained in `parameters/received.syx`, including on failure. The library entry points are `ReadSession.BlockParametersAsync` and `BlockParameterRead.CaptureAsync`.

The command identifies the configured model/firmware, samples current selection and block status, checks the requested instance is present, sends one typed `1F` query, then samples selection and block status again. Observed drift refuses a complete result. A timeout, malformed transfer or transport fault stops the session without replay. Equal endpoint samples cannot establish atomicity or exclude a transient change and return. Replies omit preset/channel identity and a request token, so a same-block notification cannot be distinguished from the query reply.

## Mapping and private formats

The shared decoder validates model, envelope, checksum, effect ID, bounded count, per-page field counts, 16-bit field packing and terminal frame. It accepts the existing 12-byte table header and the source-described 13-byte header with opaque metadata. Each body page contains at most 256 fields; the final page must exactly satisfy the header count. Tables are bounded to 4096 fields. FM9 12.00 hardware showed the two bytes after function `75` to be a little-first 14-bit page field count: 256, 256, then 76 for a 588-field Amp table. The `SectionMetadata` output retains these page counts. Positional values are assembled in arrival order; same-length page repetition cannot be distinguished from a valid next page by count alone. Repeated headers, inconsistent counts, overflow and premature endings never become complete tables.

Completed `74/75/76` tables expose every raw word and its positional editor ID. Own-model family mappings attach all matching symbolic aliases and documentary display/unit hints. The existing catalogues contain 1577 FM9 entries, 1581 FM3 entries and 1651 Axe-Fx III entries, covering 39/39/40 families respectively. Gate/Expander, Megatap and Tremolo/Panner block labels resolve to the corresponding Gate, Megatap Delay and Tremolo editor families. Actual mapping requires a qualified block-family identity and a received field at that position; catalogue totals are not verified device coverage. Unknown identities/positions remain raw. Values are not automatically scaled, converted to saved offsets or treated as writable descriptors.

Private `01` replies with subactions `09/00`, `52/00` and `1F/00` expose effect/parameter IDs, raw finite float32 bits/value, modifier metadata and bounded MSB-packed display bytes. Their names come from the configured model's catalogue. Discrete echoes may carry zero plus a display name: the raw float never establishes a type ordinal. Display bytes are rendered as Latin-1 with the raw frame retained; this is source byte-string interpretation, not a manufacturer encoding guarantee. Other subactions remain unknown, including the unsubstantiated `04/01` notification form. Private `64` results expose raw status codes without asserting universal success or persistence.

The existing passive `listen-notifications` / `fractal_listen_device_notifications` paths now use a stateful observer. They retain individual frames and emit a mapped table only after a valid ending. Orphan, interrupted and invalid sequences remain visible; a new valid header starts a fresh transfer. An unfinished table at the capture boundary produces an incomplete report. `invalid_count` includes malformed private sequences. A completed collection can contain invalid observations and is never a claim of complete device-change coverage. No passive MIDI query, edit, cache mutation or automatic refresh is sent.

## Evidence and remaining work

A toolkit FM9 12.00 trial completed one 588-field Amp table after correcting the source-inferred section-ID interpretation: the apparent section bytes were page field counts. The initial partial failure and successful complete read are both retained in the [physical trial record](live-parameters-validation.json). A later read-only USB trial completed one table each for Compressor, Cab, Reverb, Delay, Chorus, Wah and Drive, with 148, 424, 292, 364, 128, 100 and 176 positional fields respectively. Each table had a valid ending and matching before/after selection and block-status samples. Integrity-checked saved-image reads before and after the series were byte-identical. These observations qualify only those table reads on FM9 12.00; they do not establish other instances, models, firmware, parameter writes or physical display scales.
