## Evidence boundaries

Software coverage, manufacturer features and physical compatibility are separate claims. Common model-aware operations do not establish hardware qualification for every model, firmware or block family. Aggregate hardware results are retained in operation-specific records; personal targets, port choices and settings are omitted.

- [Device support](device-support.md) maps common contracts to model-specific evidence.
- [Reading qualification](hardware-validation.md) separates complete inventories from sampled checks and retains negative observations.
- [Block insertion](block-insertion-execution.md) separates placement, parameter editing and routing; exact instances and cells are caller inputs.
- [Preset restoration](preset-restore.md) distinguishes file integrity, temporary upload, persistence and reload verification.
- [Scene MIDI execution](scene-midi-execution.md) and [recovery](scene-midi-recovery.md) retain complete preservation, fresh-state reconciliation and explicit undo boundaries.
- [MCP validation](mcp-validation.json) establishes software interoperability and execution guards; its linked [client record](claude-desktop-validation.json) separately limits physical qualification.

The [machine-readable audit](capability-audit.json) and [capability catalogue](../knowledge-base/catalog/capabilities.json) retain the same generalized task records. Synthetic fixtures demonstrate software behavior; they are not recommended device settings.
