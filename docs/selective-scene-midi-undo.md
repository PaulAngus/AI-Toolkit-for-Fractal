# Selective undo of a saved Scene MIDI edit

Release 0.28.0 can plan selective undo from either a completed saved general-edit receipt containing only existing Scene MIDI message operations or a completed item in the persistent Scene MIDI recovery store. The planner is offline and opens no MIDI ports. Whole-backup undo and explicit continuation remain available through their existing contracts.

Supply an integrity-checked capture of the **current saved preset** and one exact evidence source. For a general-edit receipt, supply the private execution directory and SHA-256 of its `attempt.json`; the receipt must contain a verified Save and Reload. For the persistent recovery store, supply its directory, exact current `state.private.json` SHA-256 and one completed item slot. Pending, undoing and terminal items are refused. Planning accepts canonical schema-1 recovery release labels from 0.8.0 through the current release read-only, provided the retained original, plan, saved result and Reload all revalidate under current semantics. An incompatible actual historical record is refused; no older record is rewritten. Ordinary mutable recovery import still requires the current release. General-edit receipts from 0.25.0 through 0.27.0 revalidate their complete plan report and expected image, allowing only the release tag to differ.

The planner revalidates the original and verified result, confirms the same slot and exact Scene MIDI instance layout, and derives ownership from differences in the four saved message banks. There must be no historical changes outside that table. For each owned row, the current four raw words must equal either the recorded result or original. Any third value is a conflict. One typed, backup-sourced `restore-scene-midi-rows` operation copies only those four original words per owned row, including inactive words on Off rows, with exact current-word guards and a hash-bound original capture. Later changes to other rows and preset settings remain in the new baseline and authored result. A repeated request whose owned rows are already restored is a no-op. Reported `owned_rows` and `already_restored_rows` are one-based flattened indices 1–64: `(scene - 1) × 8 + message_slot`.

CLI planning:

```text
fractal plan-selective-scene-midi-undo --receipt COMPLETED_EDIT_DIRECTORY --receipt-hash ATTEMPT_SHA256 --capture CURRENT_SAVED.syx --destination NEW_BUNDLE_DIRECTORY
fractal plan-selective-recovery-undo --recovery PRIVATE_RECOVERY_DIRECTORY --state-hash CURRENT_STATE_SHA256 --slot ZERO_BASED --capture CURRENT_SAVED.syx --destination NEW_BUNDLE_DIRECTORY
```

The MCP equivalents are `fractal_plan_selective_scene_midi_undo` (completed general-edit receipt) and `fractal_plan_selective_recovery_undo` (completed recovery-store item). Each also takes a `backup_artifact` and `slot`. The backup artifact must contain the caller-selected current saved capture; planning does not query a device or certify when that capture was taken. The returned bundle goes through ordinary `fractal_prepare_preset_edit` and a fresh exact trusted-host review. At execution, complete saved and loaded preflight must match the new baseline, then the normal upload, independent live table check, Save and Reload verify the whole authored result. An intervening change stops execution. Planning and executing the new edit do not mutate or mark the older recovery store undone; its prior exact-result continuation will then conflict with the changed preset.

The [offline validation record](selective-scene-midi-undo-validation.json) covers FM9, FM3 and both Axe-Fx III capacities, including full inactive-word restoration, later unrelated row/name preservation, repeat no-op, stale hashes, changed owned rows, prior-release read-only import and final saved/reloaded equality. Prior-release coverage relabels current-schema fixtures; archived historical bytes have not been validated. These tests do not establish hardware behavior. Other historical edit types, Scene MIDI block insertion/removal, unfinished recovery items and partial saved/unsaved work remain outside this selective path.
