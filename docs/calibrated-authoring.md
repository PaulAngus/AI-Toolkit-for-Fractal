# Capture-backed parameter, Scene Ignore and modifier authoring

Release 0.23.0 adds exact-value calibration evidence, explicit Scene Ignore edits, modifier source changes and complete modifier templates to the shared saved-image planner. CLI and MCP preparation use the ordinary complete-image executor, exact review, preservation checks, Save/Reload, undo and reconciliation. Supported built-in setters and all device definitions remain enabled. A later FM9 12.00 test qualified one existing modifier-source change through Save/Reload and exact undo; other operations in this document retain their stated evidence scope.

## Exact-value calibrations

`calibrate-parameter --request REQUEST_JSON --destination NEW_DIRECTORY` validates a `ParameterCalibration` document offline. It contains `schema_version: 1`, exact `model`, `capacity`, caller-recorded `firmware`, `effect_id`, `channel`, semantic `key`, `unit`, `kind: "parameter"`, and 2–16 `samples`. Each sample supplies a finite declared `value`, SHA-256 `sha256` and base64 complete saved `capture`.

The shared resolver checks the complete captures' integrity and requires the same saved slot, uniquely identified instance, record shape and body length. All decompressed body bytes must match except one uint16 word in the selected channel's settings region. Grid, structural headers, scene assignments and saved default scene cannot become calibration targets. Existing descriptor identities/units cannot be relabelled, and numeric type selectors continue to use their ordinary explicit preservation policy.

The output retains every witness in `calibration.json`; `calibration-report.json` records the inferred relative word, exact values/raw words, hashes, shape and a block-context hash that excludes that word. Declared values must be distinct and map to distinct raw words. These are caller-labelled observations: byte integrity cannot prove the labels, physical scale or actual hardware origin. Synthetic samples remain synthetic; no capture or device calibration is fabricated.

`set-calibrated-parameter` takes `effect_id`, `channel`, `key`, `unit`, `calibrated_value` and the complete `calibration` document. It accepts only an exact witnessed value, requires the current raw value to have a witness, and requires the rest of the instance settings to match the calibration context. It does not interpolate, extrapolate, infer a saved offset from an editor ID, or reuse a calibration across models/firmware/block contexts. Changed block context needs new evidence. Edits to other blocks and modifier records can compose; a same-block type/template/other-setting change may invalidate that calibration. Conflicting names for the same calibrated word cannot silently overwrite each other.

The new `calibrated_value` field accepts signed physical-value labels while existing `value` contracts retain their prior bounds. Requests and private bundles retain complete witness bytes. Review reports omit those bytes while retaining their hashes and before/after values; bundle reopening revalidates the evidence before execution. Repeat desired values produce no change.

MCP `fractal_calibrate_saved_parameter` takes the same semantic context plus `samples` of `{backup_artifact, slot, value}`. Each witness must come from an integrity-checked export matching the configured model/capacity/firmware. It requires no live-read or write access. Use its returned `calibration_artifact` on `fractal_plan_preset_edit`; the adapter embeds the validated document into the private request. Execution still requires the existing exact trusted-host approval.

For a modifier value, use `kind: "modifier"`, the target `effect_id`, no channel, `modifier_slot`, exact `expected_binding: [source, effect, parameter]`, a `modifier.*` key, a caller-declared unit and 2–16 labelled captures. Each capture must have the same saved slot, 25-word modifier record, binding and uniquely placed target block; the bodies must differ in exactly one modifier settings word. Source and target binding words cannot be calibrated. A known source-mapped field must use its known word and name; an unknown name cannot relabel a mapped word. `set-calibrated-modifier` takes the slot, binding, key, unit, exact `calibrated_value` and calibration document (or MCP `calibration_artifact`). The current raw word and requested value both need witnesses, and the other modifier words and target-block instance must match their captured context. It changes one word only. Repeat values are no-ops; conflicts, changed context and interpolation are refused.

This path permits exact caller-labelled Scale/Offset or Attack/Release display values and numeric selector labels when suitable captures exist. The labels and physical meaning remain unverified until the captures and their provenance are assessed; the tool does not derive a general display scale, milliseconds conversion or Damping Type enum. It does not turn synthetic fixtures into hardware evidence. The built-in `saved-normalized` setters and same-binding selector-copy path remain available independently.

## Scene Ignore

Create a calibration with `kind: "scene-ignore"`, no channel, a key ending in `.scene_ignore`, unit `boolean` and exactly two declared values: 0 (off) and 1 (on). The same strict single-word/body-preservation checks apply, with a block-scoped settings region. `set-scene-ignore` takes `effect_id`, that `key`, `unit: "boolean"`, explicit `enabled` and `calibration` (or MCP `calibration_artifact`).

This provides authoring when retained off/on witnesses establish the word for that block context. It does not guess a universal Scene Ignore offset or assume raw words must themselves equal 0/1. Multiword representations require additional support. Turning Scene Ignore on/off does not rewrite the saved scene channel/bypass assignments.

## Modifiers

Offline `decode-edit` now reports parsed 25×1 modifier slots with numeric source, effect/parameter binding, settings offset and raw settings. The modifier payload is 25 words beginning at record+34; the source is word 0 and the target effect/parameter are words 8/9. The following instance prefix is excluded. This is an interpretation of the pinned Gen3 open implementation, not a manufacturer guarantee or new physical test.

- `set-modifier-source` takes an existing `modifier_slot`, numeric `source_id` (0–16383) and `expected_binding: [source, effect, parameter]`. It changes only the source word and preserves the curve and other settings. Source names and effective behavior are not inferred for unknown IDs.
- `copy-modifier` takes `modifier_slot`, `template_modifier_slot`, `expected_binding`, a complete same-model/firmware `template_capture`, its `template_sha256` and `template_firmware`. MCP instead uses `template_artifact`/`template_slot` from an export. It copies the complete explicit settings, including the donor's binding and opaque curve, into an existing parsed slot. The target effect must be placed and another parsed slot cannot already own the same target parameter. A vacant slot can be initialized from this template; no curve defaults or extra slots are invented.

Existing bindings must match the expected ownership precondition. An already identical desired result is a no-op. Numeric modifier parameter IDs remain qualified binding data; they are not automatically equated to saved offsets or borrowed from another model. The later [exact Axe-Fx III 32.02 profile](builtin-scales.md) adds selected named curve, saved-normalized and donor-backed raw-selector fields. Other model/firmware mappings, full display-value conversion, source-name catalogues, additional storage layouts and physical effective behavior remain extensions.
