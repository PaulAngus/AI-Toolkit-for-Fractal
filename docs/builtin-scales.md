# Built-in saved scales and named modifier curves

Release 0.24.0 added 57 built-in parameter scales and named modifier curve authoring to the shared offline planner and complete-image executor. Release 0.34.0 adds two exact positive-integer saved fields, bringing the current profile to 59. Existing mapped setters, capture calibrations, Scene Ignore, modifier source changes and templates remain enabled on all device definitions.

## Scope and discovery

`edit-catalogue` and MCP `fractal_query_parameters` return `builtin_scales`: exact model/firmware scope, catalogue hash, semantic keys, instance IDs, record widths, physical bounds, units, tapers and provenance. The initial scale profile is **Axe-Fx III firmware 32.02**, for either explicitly established capacity. Other firmware/model contexts return no entries from this profile; their existing operations remain available. FM9/FM3 never inherit Axe-Fx III scales or parameter numbers.

The 59 fields cover Amp, Compressor, Gate/Expander, Reverb, Chorus, Flanger, Drive, Megatap Delay, Parametric EQ, Delay, Phaser and Multiband Compressor. Fields include signed dB levels/thresholds, bipolar feedback/tone, logarithmic frequencies and timings, linear delay/reverb times, EQ gains and Q, plus positive integer Drive Bit Reduce and Megatap Number of Taps. Only exact matching four-channel record shapes are edited. A numeric editor ID alone is not a saved offset: these descriptors join the source's explicit saved-word laws and same-model word census to the contained instance layout, whose payload begins at shape offset +34. The word address is payload +2×(channel×columns + parameter index). This join is source-derived; it has not been independently tested on hardware here.

`set-scaled-parameter` takes `effect_id`, `channel`, `key`, `physical_value` and `unit`. For example, a matching profile accepts `amp.level`, `physical_value: -15`, `unit: "dB"`. Signed physical values have a separate field so existing `value` contracts do not change. `set-parameter` continues to serve its existing mappings; use the new operation for these scales.

Linear normalization is `(value-min)/(max-min)`; logarithmic normalization is `log(value/min)/log(max/min)`. Those saved words use round-half-up of normalized×65534. Drive Bit Reduce accepts only whole 0–24 `bits`; Megatap Number of Taps accepts only whole 1–128 `taps`. Their positive saved words equal the integer values exactly, without normalization. The pinned source reports a Megatap feedback-tap readout reclamp when its tap count changes; the toolkit has not physically tested whether that causes an additional saved-word change. The guarded executor must still verify the complete authored image before and after Save. The 65534 denominator is deliberately distinct from the existing source-qualified FM9/FM3 0–10 mappings. Live SET float scales are a different domain and are never substituted. Reviews include requested/effective values and original/result raw words. Out-of-range, fractional integer, non-finite, wrong-unit, wrong-shape and wrong-firmware requests are rejected without changing other operations. Raw 65535 remains an unknown sentinel in these fields, not a coerced physical value.

## Named modifier fields

`set-modifier-parameter` takes `modifier_slot`, exact `expected_binding: [source, effect, parameter]`, `key`, `physical_value` and `unit`. It edits one word in an existing parsed 25-word modifier payload and preserves its sources, binding, unrelated curve settings and neighboring record prefix.

For the matching scale profile, these keys use percent units and the 0–100 range:

- `modifier.start`, `modifier.mid`, `modifier.end`, `modifier.slope`
- `modifier.off_value`, `modifier.source1_scale`, `modifier.source2_scale`

`modifier.minimum` and `modifier.maximum` use the target parameter's physical scale and unit when its binding resolves to one of the continuous built-in fields and a uniquely placed matching record. Integer target endpoint storage is not established and is excluded from these named Min/Max mappings. Min may exceed Max for reversed control. No sorting, clamping or curve reset is applied. A Delay Feedback modifier can therefore explicitly set Min to 75% and Max to -75%. Decoded modifiers expose these named values, raw words and scales.

The exact Axe-Fx III 32.02 profile also maps `modifier.attack` (word 7), `modifier.scale` (13), `modifier.offset` (14) and `modifier.release` (15). They use `physical_value` from 0 to 1 with unit `saved-normalized`: this is the saved word divided by 65534, **not** a millisecond, percent or displayed Scale/Offset value. This gives exact one-word authoring without inventing a display conversion. Raw 65535 remains an unknown sentinel. The decoder reports the four fractions and their raw words.

The same profile decodes `modifier.damping_type` at word 24 as an unlabelled raw selector index. `copy-modifier-selector` can replace **only** that word from a complete, integrity-checked same-model preset capture with a matching declared firmware. It takes `modifier_slot`, exact `expected_binding`, `key: "modifier.damping_type"`, `template_modifier_slot`, `template_capture`, `template_sha256` and `template_firmware`; MCP uses a retained export's `template_artifact` and `template_slot` instead of the capture bytes and checks its device context. CLI firmware provenance remains caller-declared. The donor must have the same source/effect/parameter binding. No index-to-Linear/Exponential mapping is inferred, so a numeric selector setter is not exposed. This operation can preserve the target's entire remaining modifier curve when a trustworthy donor is available.

Ownership mismatches that would change a curve, duplicate assignments and unknown keys fail planning. An already identical curve value can remain unchanged after a source change, provided its target effect/parameter still matches; this permits repeated compound source/curve requests without overwriting another binding. Existing complete modifier templates and numeric source edits remain available independently of named-scale coverage. [Exact modifier calibration witnesses](calibrated-authoring.md) can now set caller-labelled display values for one matching binding/context without deriving a general conversion. Attack/Release time conversion, Scale/Offset display conversion, damping selector labels, extra storage layouts and unknown target scales are not guessed. Stored values do not establish effective audible behavior under tempo, type dependencies, modifier channel limits or other controllers.

## Provenance and remaining evidence

The contained factual catalogue is [saved-value-scales.json](../knowledge-base/catalog/saved-value-scales.json). It adapts selected data from **Big Saurus**, [Axe-Fx III SysEx & Parameter Maps revision 4463ae9b7e388d2fe98e24fdd7068b1c35865277](https://github.com/BigSaurus/axefx-sysex-maps/tree/4463ae9b7e388d2fe98e24fdd7068b1c35865277), under [CC BY 4.0](https://creativecommons.org/licenses/by/4.0/); [retained licence and notice](big-saurus-license.txt). Changes: selected/normalized fields, deduplicated aliases, explicit firmware/shape binding, excluded unresolved integer/sentinel encodings and differently scoped observations. No upstream private capture names or session narratives are included.

Pinned inputs are `maps/param_word_laws.json`, `maps/axefx_sysex_map.json` and `ADVANCED_COMMANDS.md`; exact SHA-256 values and locators accompany the catalogue. These are upstream-reported observations and cache-derived inferences. Their raw hardware captures are not retained here, and their confidence labels are not new toolkit hardware qualification. Modifier payload structure also uses the independently pinned `gen3-body` source already retained in the toolkit's source register. The [Axe-Fx III manual](https://www.fractalaudio.com/downloads/manuals/axe-fx-3/Axe-Fx-III-Owners-Manual.pdf), modifier section, documents curve controls and reversed Min/Max; it does not document saved-word serialization.

The pinned word-law source has 68 entries: 59 distinct safe fields are now mapped. Two further entries duplicate existing Delay fields. Compressor and Multiband Compressor ratio maxima display INFINITE; signed Reverb Voice Shift storage and differently scoped Compressor attack/release observations remain unresolved. The pinned 25-word source identifies Scale, Offset, Attack, Release and Damping Type positions and reports continuous words normalized by 65534; the [manufacturer manual](https://www.fractalaudio.com/downloads/manuals/axe-fx-3/Axe-Fx-III-Owners-Manual.pdf) describes their effects but not their saved serialization or complete display ranges. The saved-normalized and donor-copy paths above retain that boundary. Wider FM9/FM3 built-in scales, additional firmware, physical-value conversion for these modifier controls, selector labels and hardware verification remain evidence work. Capture-backed exact-value setters remain available where callers already have suitable witnesses.

CLI/MCP plans use the existing upload, verification, Save/Reload, exact undo and review contracts. No hardware acquisition is performed during calibration, discovery, planning or normal CI. See [software validation](builtin-scales-validation.json) and the [audit](capability-audit.md).
