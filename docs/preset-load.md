# Explicitly load a saved preset

`PresetLoadScope` and `ReadSession.AuthorizePresetLoad`, `PreparePresetLoadAsync` and `VerifyPresetLoadAsync` implement one caller-requested preset load across all model definitions. This is separate from automatic edit/recovery navigation, which always refuses saved/live differences.

Retain complete integrity-checked current saved, current loaded and target saved captures before requesting navigation. Bind the exact model/firmware, current slot/name/scene and target slot to those captures. Loaded captures have opaque out-of-capacity addressing and are never relabelled as saved presets. If current saved/live images differ, explicitly choose whether to discard those differences; the default preservation rule rejects the request without discard authorization.

The separately opted-in checker retains all three private captures before opening ports. Immediately before its one typed Load, the session rechecks current selection, complete current saved/live images and target saved bytes. A late change, wrong firmware or selection drift prevents the load. A recalled preset may retain or reset its selected scene, regardless of the scene selected before recall. The scope reviews an optional absolute scene command for every load. It sends that command only when readback shows a mismatch and proves both saved images remain exact while the loaded body differs from the target solely in its selected-scene word, with opaque raw bytes preserved. An already-correct scene consumes no additional wire command. Final readback must verify the complete target buffer and saved default scene. There is no Save, upload or blind load retry. Retaining an unsaved buffer as evidence does not by itself qualify future restoration of that buffer.

Use `--hardware --load-preset --request REQUEST_JSON --expected-hash REQUEST_SHA256`. `--validate-only true` opens no ports. Live execution also requires `--input`, `--output` and a new private `--destination`. Request schema 1 contains `model`, `capacity`, `firmware`, `current_slot`, `current_scene`, `target_slot`, `discard_changes`, and `current_saved`, `current_loaded`, `target_saved` objects with local `file` names and exact `sha256`. Captures reside beside the request; no personal defaults are supplied.

The wire builder is the existing model-qualified `EditorCommand.ReloadPreset`, with pinned source locators in [the reading map](../knowledge-base/reference-map.md) and [editor evidence](editing-pilot.md). Current physical qualification is recorded with [recovery validation](scene-midi-recovery-validation.json); synthetic model tests do not establish other-model hardware behavior. Loading presets can also trigger their existing outgoing MIDI messages; downstream response is not qualified by image equality.

Release 0.9.0 adds read-only `prepare-load` to retain current saved/loaded and target bytes plus a typed load request, without sending Load. [The local MCP adapter](mcp.md) captures this context, validates/freezes it into an exact review, then reuses the scoped loader only after local operator authorization. Current loaded evidence remains available if default preservation refuses review preparation.
