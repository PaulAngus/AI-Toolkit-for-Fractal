# Explicit automatic isolated placement

The shared offline insertion planner accepts `placement_policy="first-isolated-empty"`, exposed as `--placement-policy first-isolated-empty` by both block and Scene MIDI planning CLIs and as `placement_policy` by their MCP tools. This opt-in policy is mutually exclusive with coordinates. Omitting both still reports missing placement when insertion is needed; there is no implicit default cell.

The policy uses the actual model's complete grid and chooses the first suitable empty cell in column-then-row order. It never replaces shunts or blocks. A unique existing instance is reused wherever it is, so repeating the intent produces no insertion. Full grids, ambiguous instances and uncertain local routing produce explicit per-preset conflicts. Input array order has no effect, and each selected preset can receive a different concrete location. The plan freezes those locations, baseline hashes and original cells before execution review.

Isolation follows the retained destination-mask semantics: a cell's route word describes its incoming connections from rows in the previous column. Its outgoing connections therefore appear in the following column's masks. The candidate must have a zero incoming mask and no following-column mask may reference its row. Unknown bits in following-column masks prevent establishing isolation; unrelated known routes are preserved and do not prevent a valid placement.

The same rule now guards the contained isolated insertion/removal executors and offline removal planner. The earlier preceding-column test could miss actual outgoing connections and reject unrelated routes; the new checks are verified with independent synthetic examples across every model definition. Existing connected editing remains available through the general editor.

This policy chooses isolated placement only. It does not design an audio path, select block instances, establish DSP availability, invent defaults or bypass template requirements for complete-image editing. Callers still resolve model/firmware-qualified identities and configuration. Existing execution reviews, saved-base comparisons, unsaved-work checks and complete readback remain in force. No new hardware testing is claimed.

Validation: `tests/test_block_insertion.py`, `tests/test_block_removal.py` and `tests/Fractal.Checks/GridIsolationChecks.cs` cover model bounds, input preservation, repeat intent, shunts, occupancy, actual incoming/outgoing paths, unknown masks and unrelated-route preservation. The relocated MCP pipeline exercises automatic planning through the real insertion-review helper without opening ports. Protocol attribution is the existing `gen3-grid-layout` source and contained saved-grid catalogue; no external runtime dependency is introduced.
