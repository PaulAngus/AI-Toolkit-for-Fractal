# Use the toolkit through a local MCP client

General task: give an AI client typed access to retained Fractal knowledge, reads, plans and deliberately authorized execution across FM9, FM3 and Axe-Fx III.

Start with [installation and tool contracts](../../docs/mcp.md) and [measured scope](../../docs/mcp-validation.json). Build a complete relocatable bundle, configure private artifacts and the contained runtime, then supply the server's executable/arguments to a client that launches local stdio MCP processes. Read-only/offline use starts with live access and writes disabled; a cloud-only client requires a separate connection implementation.

When reporting status, lead with setup and effective access. For a requested task, distinguish available software, required inputs and model/firmware hardware qualification. Explain limitations relevant to that task; do not turn individual validation scenarios into an arbitrary list of unsupported features. An untested hardware combination is an evidence gap, not proof that the general operation is absent.

Retrieve the reading map and search retained capabilities before broad documentation research. Capture/import complete manifests and original bytes, then use canonical Scene MIDI or chosen-cell insertion plans. Resolve zero-based targets, scenes/message slots, messages and block placement from the user request. General block insertion is implemented independently of block family. Insertion and parameter editing require separate reviews: verify the inserted block, capture fresh backups, then replan parameter edits. A single combined insertion/configuration transaction and arbitrary parameter authoring are not implemented. Hardware qualification is a separate model/firmware/block-family question; consult the operation-specific evidence rather than treating an untested combination as an absent feature.

Prepare an exact review with frozen inputs, source hashes and configured device/ports. Honor existing exact user authorization through a trusted local host approval; a model-controlled tool call cannot approve itself. Start execution once through the guarded runtime and retain its accepted job receipt. Acceptance is not completion: poll `fractal_inspect_attempt` with `wait_seconds: 20` until a verified or uncertain terminal state. Terminal inspection supplies exact result/recovery identifiers without searching long artifact listings. Cancelling a status wait stops only that wait; a user-requested `fractal_cancel_attempt` or server shutdown stops owned device work. Inspect any conflict or uncertainty. Never repeat a consumed approval. Lost replies and fresh sessions use attempt/artifact discovery, updated recovery heads and fresh explicit continuation reviews.

The adapter's tests establish protocol interoperability and software boundaries, not new hardware compatibility. Use per-model/firmware operation records for actual device evidence. Public MCP resources contain reusable documentation; private preset bytes, configuration, approvals and per-user histories remain outside distributable artifacts.
